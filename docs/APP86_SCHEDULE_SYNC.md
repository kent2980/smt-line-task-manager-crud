# App86 日別予定・予定時刻同期

## 目的

Excelの日程をApp86へ同期しつつ、`sub_schedule` の過去予定を物理削除せず履歴として保持します。

Excelは現行予定の正本ですが、既存テーブル行は削除しません。同期対象期間の旧予定を `有効判定 = False` にし、新しい予定を `有効判定 = True` で追加します。

## sub_schedule の更新方針

### 既存行は物理削除しない

同期対象となったレコードの `sub_schedule` は次の順序で更新します。

1. 既存の `sub_schedule` 行をすべて行ID付きで保持する
2. Excel日付範囲内の既存行だけ `有効判定 = False` にする
3. Excel日付範囲外の既存行は変更しない
4. Excelから生成した新しい予定行を末尾へ追加する
5. 新規予定行は `有効判定 = True` とする

既に `False` の行も削除しません。既存行をpayloadから省略するとkintoneテーブル行が削除される可能性があるため、既存行IDを取得できない場合は安全のため更新を中止します。

### Excel日付範囲

各Excelの予定日ヘッダー（I列～AE列、全ページ）から有効な日付を取得し、最小日付～最大日付を同期日付範囲とします。

予定台数が入っていない日もヘッダーに日付があれば範囲に含みます。これにより、Excelから予定自体が消えた日でもkintone側の旧予定を `False` にできます。

例:

- 最小日付: `2026-09-14`
- 最大日付: `2026-10-06`

この場合、`2026-09-14 <= sub_schedule_date <= 2026-10-06` が同期対象期間です。

## レコードの追加・更新条件

### 新規追加

Excel側に存在し、kintone側に同じ `line_lot_number` が存在しないレコードは従来どおりPOSTします。

POSTする `sub_schedule` 行はすべて `有効判定 = True` です。

### 更新

更新対象は次のOR条件です。

1. **既存条件**: Excel側とkintone側で `line_lot_number` が一致する
2. **追加条件**: kintone側の `sub_schedule` にExcel日付範囲内の `sub_schedule_date` を持つ既存行が1件以上ある

追加条件では、Excel側に同一 `line_lot_number` が存在する必要はありません。

#### 既存条件で更新されるレコード

親フィールドは従来どおりExcel値で同期します。

ただし `sub_schedule` は置換せず、既存行を保持・範囲内をFalse化・新予定をTrueで追加します。

#### 追加条件だけで更新されるレコード

`sub_schedule` フィールドだけをPUTします。

`line_name`、`lot_number`、`index` などの親フィールドは変更しません。Excelから生産指図自体が消えた場合でも、その期間の旧予定だけを無効化できます。

## データの責務

| 項目 | 正本 / 算出元 |
| --- | --- |
| `sub_schedule_date` | Excel |
| `sub_lot_volume` | Excel |
| `sub_index` | Excel |
| `sub_change_time` | Excel AP列。ただし日跨ぎ連続予定の2列目以降は0 |
| `有効判定` | 同期処理。新規はTrue、同期対象期間の旧予定はFalse |
| `生産時間` | kintone Calc。切替時間を含む |
| `予定開始日時` | 本スクリプトで算出 |
| `予定終了日時` | 本スクリプトで算出 |
| `休憩時間` | 本スクリプトで算出（分） |

`生産時間` はCalcフィールドなのでAPIから直接更新しません。Excel同期完了後にApp86を再GETし、kintoneが再計算した最新値を使用します。

## 日跨ぎ生産指図の切替時間

同一Excel行の予定台数セル（I列～AE列）が隣接して入力されている場合、同じ生産指図が翌日へ継続しているものとして扱います。

- 連続区間の先頭セル: AP列の切替時間を `sub_change_time` に登録
- 右隣以降の連続セル: `sub_change_time = 0`
- 空列を1列以上挟んで次の予定セルがある場合: 新しい連続区間としてAP列の切替時間を再登録

## 予定開始・終了・休憩時間の計算対象

`sub_schedule.有効判定` が明示的に **`True` の行だけ**を計算対象にします。

`False`、空欄、その他の値は計算対象に含めません。

無効行の既存 `予定開始日時`、`予定終了日時`、`休憩時間` は履歴として保持し、再計算で上書きしません。

### 計算ルール

予定は `sub_schedule_date × line_name` ごとに独立して計算します。

- 各グループの開始: 08:30
- 並び順: `index` 昇順、同値時は `$id` 昇順、同一レコード内はテーブル行順
- 作業時間: `生産時間` のみ
- 10:00-10:10: 10分休憩
- 12:00-12:40: 40分休憩
- 15:00-15:10: 10分休憩
- 通常終了時刻17:30では打ち切らない
- 17:30を超える結果も保存する
- 日付を跨ぐ結果も保存するが、翌日の予定グループは翌日08:30から独立して計算する
- 名目上の終了時刻が休憩開始時刻と一致した場合、その休憩を当該予定に含める

## 予定再計算の影響範囲

通常同期では次の日付×ラインを再計算対象にします。

- 今回Excelから追加した新規予定の日付×ライン
- Excel日付範囲内に存在して無効化対象となったkintone既存予定の日付×ライン

この対象抽出は `line_lot_number` 一致に限定しません。レコード更新条件と同じExcel日付範囲を使用します。

## 通常実行

```powershell
.\Main.ps1
```

変更対象Excelを同期したあと、影響する日付×ラインの有効予定だけを再計算します。

ファイルタイムスタンプは **Excel同期と予定再計算の両方が成功した後** に確定します。

## 強制全件同期

```powershell
.\Main.ps1 -ForceFullSync
```

タイムスタンプと日次同期済み状態を無視してGC01-GC09の全Excelを再読込します。

全件同期でも同じ履歴保持ルールを使用します。

1. 全Excelを再読込
2. Excel日付範囲を取得
3. 対象期間の既存 `sub_schedule` をFalse化
4. 新しい予定をTrueで追加
5. App86を再GETしてCalc `生産時間` を取得
6. `有効判定 = True` の予定だけ開始/終了/休憩時間を再計算
7. 全処理成功後にファイルタイムスタンプを確定

## 予定時刻だけ全件再計算

```powershell
.\Main.ps1 -RecalculateScheduleOnly
```

Excelは読みません。現在App86に登録されている `sub_schedule` のうち、`有効判定 = True` の行だけを使用して全予定を再計算します。

Falseまたは空欄の履歴行は変更しません。

## 既存データ移行

既存データで `有効判定` が空の行は、予定計算上は有効とみなしません。

本変更反映後に `-ForceFullSync` を実行すると、現在のExcel日付範囲内にある既存行はFalse化され、Excel由来の新予定がTrueで追加されます。

## 注意事項

- `lot_number` が空のExcel行は新規作成・通常更新対象外です。
- App86に残っている `lot_number` 空レコードは予定再計算対象外です。
- `record_type = SETTING` は予定計算対象外です。
- `生産時間` はCalcのためPUT payloadへ含めません。
- 予定時刻PUTでは `有効判定` を含めて保持します。
- `sub_schedule` 既存行は物理削除しません。
