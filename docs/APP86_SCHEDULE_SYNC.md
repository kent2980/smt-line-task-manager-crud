# App86 日別予定・予定時刻同期

## 目的

Excelの日程再割り付けをApp86へ同期した直後に、`sub_schedule` の日別切替時間と予定開始・終了・休憩時間を完成させます。

Excelを日程の正本とし、既存の `sub_schedule` を最新の日程で丸ごと置換する既存仕様は維持します。古い割り付けはApp86へ残しません。

## データの責務

| 項目 | 正本 / 算出元 |
| --- | --- |
| `sub_schedule_date` | Excel |
| `sub_lot_volume` | Excel |
| `sub_index` | Excel |
| `sub_change_time` | Excel AP列。ただし同一行の予定台数セルが右隣へ連続する日跨ぎ生産指図は、連続区間の2列目以降を0 |
| `生産時間` | kintone Calc |
| `予定開始日時` | 本スクリプトで算出 |
| `予定終了日時` | 本スクリプトで算出 |
| `休憩時間` | 本スクリプトで算出（分） |

`生産時間` はCalcフィールドなのでAPIから直接更新しません。Excel同期完了後にApp86を再GETし、kintoneが再計算した最新値を使用します。

`lot_number` が空のExcel行は異常データとして同期対象から除外し、App86へ新規作成・更新しません。既にApp86へ存在する `lot_number` 空レコードも予定再計算対象から除外します。

### 日跨ぎ生産指図の切替時間

同一Excel行の予定台数セル（I列～AE列）が隣接して入力されている場合、同じ生産指図が翌日へ継続しているものとして扱います。

- 連続区間の先頭セル: AP列の切替時間を `sub_change_time` に登録
- その右隣以降の連続セル: `sub_change_time = 0`
- 空列を1列以上挟んで次の予定セルがある場合: 新しい連続区間としてAP列の切替時間を再度登録

例: AP列が `0.5H` で、9/11・9/12・9/13が連続、9/14が空、9/15に再度予定がある場合、切替時間は `0.5 / 0 / 0 / 0.5` とします。

## 計算ルール

予定は `sub_schedule_date × line_name` ごとに独立して計算します。

- 各グループの開始: 08:30
- 並び順: `index` 昇順、同値時は `$id` 昇順、同一レコード内はテーブル行順
- 作業時間: `生産時間 + sub_change_time`
- `sub_change_time` 空欄: 0時間
- 10:00-10:10: 10分休憩
- 12:00-12:40: 40分休憩
- 15:00-15:10: 10分休憩
- 通常終了時刻17:30では打ち切らない
- 17:30を超える計算結果もそのまま保存する
- 日付を跨ぐ計算結果もそのまま保存するが、翌日の予定グループは翌日08:30から独立して計算する
- 名目上の終了時刻が休憩開始時刻と一致した場合、その休憩を当該予定に含める

## 通常実行

```powershell
.\Main.ps1
```

変更されたExcelを同期したあと、同期前と同期後の両方から影響を受ける `日付 × ライン` を抽出して予定を再計算します。これにより、ある日から予定が削除された場合も、その日に残った後続予定の時刻を詰め直せます。

ファイルタイムスタンプは **Excel同期と予定再計算の両方が成功した後** に確定します。予定再計算に失敗した場合はタイムスタンプを更新しないため、次回実行で再試行されます。

## 強制全件同期

```powershell
.\Main.ps1 -ForceFullSync
```

タイムスタンプと「本日全件同期済み」状態を無視してGC01-GC09の全Excelを再読込します。

処理内容:

1. 全Excelを再読込
2. Excelを正本としてApp86の対象レコードを全件POST/PUT
3. `sub_change_time` を日別予定ごとに再登録
4. App86を再GETしてCalc `生産時間` を取得
5. 全日付・全ラインの予定開始/終了/休憩時間を再計算
6. 全処理成功後にファイルタイムスタンプを確定

## 予定時刻だけ全件再計算

```powershell
.\Main.ps1 -RecalculateScheduleOnly
```

Excelは読みません。現在App86に登録されている `sub_schedule` とCalc `生産時間` を使って、全予定の開始日時・終了日時・休憩時間だけを再計算します。

休憩ロジック変更後、予定時刻データの修復、既存データへの初回投入などに使用します。

## バッチファイル

`run-full-sync.bat` を実行すると `Main.ps1 -ForceFullSync` を起動できます。

## 注意事項

- `lot_number` が空のExcel行は新規作成・更新対象外です。
- App86に残っている `lot_number` 空レコードは削除せず、そのまま保持して予定再計算からも除外します。
- `record_type = SETTING` のレコードは予定計算対象外です。
- `record_type` が空欄の既存レコードは生産レコードとして扱います。
- 予定時刻のPUTでは全 `sub_schedule` 行IDを含め、予定計算対象外の行を誤って削除しないようにします。
- `生産時間` はCalcのためPUT payloadへ含めません。
